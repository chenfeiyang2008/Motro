# Learner Dashboard Metrics

## 1. Purpose

本文件规定 Motro 学习端长期进展仪表的事实口径、视觉层级和能力标签边界。首页仍先回答“今天该做什么”；仪表位于今日计划之后，用少量高价值数据回答“我积累了什么、现在处于哪里、下一步为何值得做”。

指标必须由服务器可重建事实派生，显示值、解释文本和无障碍摘要使用同一数据源。任何实现不得为了填满界面制造估算值、伪精度、虚假百分比或没有行动含义的统计块。

## 2. Information hierarchy

### First layer — today

首屏主舞台始终是今日学习计划：主课程、当前单元、预计时间、到期复习、首复习、新学习和唯一主操作。长期指标不得与“开始学习”竞争，也不能导致 390px 高度下主要操作被数据面板推到不可见区域。

### Second layer — learning observatory

长期进展使用一个连续、不透明的“学习观测面”，内部通过排版、分隔、共同坐标和留白组织，不把每个数字装进独立卡片。建议顺序：

1. 一个主事实：`已稳定词汇`；
2. 一条词汇成熟路径：已接触 → 双向首测完成 → 已稳定；
3. 当前课程位置与单元完成度；
4. 最近 7 天学习节奏；
5. 需要注意的到期负荷。

桌面端可将主事实与趋势并列，移动端按上述顺序纵向排列。折叠次级细节时仍保留主结论和准确数值。

## 3. Authoritative metrics

### `exposedLexicalEntryCount` — 已接触词汇

- 口径：存在 `LearningExposure` 的不同 `lexical_entry_id` 数量；跨课程去重。
- 展示：`已接触 1,240 个词`。
- 解释：表示系统曾向学习者正式展示，不表示已经测试或掌握。

### `initiallyReviewedCourseItemCount` — 双向首测完成词项

- 口径：一个课程词项的英文→中文和中文→英文方向都存在首次有效 `ReviewEvent`。
- 单位必须写“词项”，因为同一全局词条在不同课程可以有不同课程释义和学习历史。
- 展示：`双向首测完成 760 个词项`。

### `stableLexicalEntryCount` — 已稳定词汇

- 口径：按全局 `lexical_entry_id` 去重；至少有一个仍保留学习历史的课程词项，其两个方向的 FSRS 预计间隔均达到 21 天。
- 展示：`已稳定词汇 428`，并提供固定解释：`按双向卡预计间隔均达到 21 天计算，不代表永久掌握。`
- 这是首页长期进展的主指标，但不得命名为“永久掌握”“词汇能力总量”或“真实词汇量”。

### `stableCourseItemCount` — 当前课程稳定词项

- 口径：当前主课程 current release 中，两个方向预计间隔均达到 21 天的不同课程词项数量。
- 与当前发布版本总词项数配对显示，例如 `当前课程已稳定 128 / 800`。
- 发布版本切换后分母与 current release 一致；历史学习事实保留，但不混入当前课程完成率。

### `currentCoursePosition` — 当前课程位置

- 口径：发布课程标注、当前最高已解锁单元和总单元数。
- 展示示例：`高中核心词汇 · 第 3 / 12 单元`。
- 必须附短标签 `课程进度`；这不是英语能力测评。

### `reviewRhythm7d` — 七日学习节奏

- 口径：按用户时区聚合最近 7 个完整/当前本地日的有效、不可变 `ReviewEvent` 数量；幂等重放不重复计数。
- 图形：七个对齐零基线的小柱或点线标记，今天明确标注；同时提供文字摘要，例如 `最近 7 天学习 5 天，共完成 84 次有效复习。`
- 不将 XP 当作学习量，不用挑战积分代替日常学习事实。

### `dueLoad` — 到期负荷

- 口径：当前主课程 current release 中，截至服务器计算时刻已到期且仍符合计划资格的学习卡数量。
- 展示：`现在有 18 张到期卡`，并与今日计划直接关联。
- 这是可行动事实；当为 0 时用平静状态 `当前没有逾期复习`，不制造危机感。

### `streakDays` — 连续学习

- 阶段边界：只有阶段 7 建立版本化游戏规则与权威连续天数事实后才可显示；阶段 5/6 的 UI 必须完全省略，不以本地推算或占位数代替。
- 口径：复用版本化游戏规则与用户时区下的连续天数事实，保护日明确标识；不能由前端根据七日图临时推算。
- 展示：作为七日节奏旁的次级事实，例如 `连续学习 12 天`，不使用倒计时、威胁或损失厌恶文案。
- 连续天数表达习惯，不表达掌握程度或能力；它不能进入已稳定词汇、课程进度或能力参考的计算。

## 4. Ability and level policy

### V1 allowed

- 发布课程自身的受控标签，例如“高中核心词汇”；
- 当前单元、课程完成度和 Motro 内部学习阶段；
- 客观测验明确测到的词汇题表现，并说明题型、范围和日期；
- “课程进度”“词汇学习参考”等有限、准确措辞。

### V1 forbidden

不得从以下任何单项或组合直接推导 CEFR A1–C2、雅思分数、高考分数、综合英语能力或“超过多少用户”：

- 已接触/稳定词汇数量；
- XP、连续天数、徽章或排行榜；
- FSRS 稳定性、预计间隔或按时复习率；
- 课程完成百分比；
- 周挑战积分或单一词汇测验正确率。

CEFR 官方描述覆盖接收、产出、互动、调解和语言质量等多个维度；词汇广度只是词汇范围的一部分。把词数直接换算成 CEFR 会制造错误权威感。

### Future calibrated reference

未来若要显示 `测评参考区间`，必须先有独立产品/测量规格，并同时满足：

- 客观、版本化的测评蓝图与题库范围；
- 覆盖所声明能力维度，不能只考单词识别；
- 文档化的标准设定、样本、校准方法和有效期；
- 可重算的评分版本和服务器事实；
- 显示范围而非伪精确单点，例如 `B1 参考区间`；
- 紧邻显示“测了什么”、测评日期和限制说明；
- 不把参考区间写成永久身份，例如禁止“你是 B1”。

在这些条件满足前，UI 用 `课程进度，不是能力测评`，不显示灰色占位 CEFR 仪表。

## 5. Visual grammar

- 主数字使用清晰的排版比例和 tabular numerals，单位与定义始终可见；不使用无上下文的大号数字。
- 成熟路径适合用单条分段轨道或三个共轴数值表达，不使用三个同权 KPI 卡片。
- 数量没有固定上限时禁止使用环形进度、速度表或百分比仪表；当前课程完成度有真实分母时才允许显示百分比。
- 时间趋势使用零基线柱形或清晰折线；不要用面积、3D、透视、渐变填充或截断坐标夸大变化。
- 数据自身最突出，网格、轴和装饰退后。每张图先给结论式标题，再给时间范围和单位。
- 颜色只强调当前、目标或异常，不单独编码类别；同时使用标签、位置、形状或纹理。
- 重要数据默认可见，不要求悬停或拖动才能得知。交互图表的整个绘图区提供足够命中范围。
- 每张图提供同数据的文本摘要；复杂图提供可键盘访问的数据表或列表。读屏顺序按时间或逻辑顺序，不按视觉装饰顺序。

## 6. Motion for data

- 首次加载使用结构占位后静态落位，不从 0 滚到真实数字。
- 只有刚完成学习、主动切换时间范围或服务器确认状态变化时才过渡数据；过渡不得暗示没有发生的增长。
- 主数值优先直接更新并辅以 120–160ms 的颜色/透明度确认；若数字字形过渡影响阅读，立即替换。
- 柱、线或进度轨道使用稳定坐标系更新；范围变化必须先更新标签或以文字提示，不能悄悄重标坐标轴。
- 图表变化必须同步更新文本摘要和适度的 live region；不能只依靠运动让用户发现变化。
- `prefers-reduced-motion: reduce` 下所有图形直接到达终态，保留文本变化、焦点与状态提示。

## 7. Empty, loading and uncertainty

- 数据不足时说明需要什么事实，例如 `完成首次学习后，这里会显示词汇成熟进展`，不要展示假数据或全零仪表墙。
- 部分请求失败时保留可证实的数据，明确标出暂不可用的区域并提供重试；不能把缓存旧值伪装为最新值。
- 每个派生指标返回或内部携带 `asOf` 计算时间；对时间敏感的到期负荷显示更新时间。
- 预测性指标若未来加入，必须显示模型/规则版本、时间点和不确定性。首版不展示未经验证的“预计掌握率”。

## 8. Acceptance

- 390px 首屏仍能看到今日任务和主要操作；长期观测面位于其后。
- 768px 与 1440px 使用相同信息顺序，不因宽度增加无意义指标。
- 所有口径有领域/集成测试；跨课程去重、current release 边界、用户时区和幂等事件均有真实 PostgreSQL 证据。
- 截图与 E2E 覆盖空数据、部分数据、长课程名、大数值、网络失败、数据刷新和 reduced motion。
- 人工验收能回答每个数字来自哪里、表示什么、不表示什么。
